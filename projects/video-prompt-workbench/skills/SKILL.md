# 反推视频 Prompt 完整性规则

在视频或图片完成反推后、进入视频生成前使用本 skill。

目标不是把 prompt 写长，而是把会导致生成失败或结果跑偏的缺口找出来：动作、运镜、转场、字幕/口播、声音、参考素材绑定、Dify 线路和 prompt 长度。

## 必要输入

- `source`：`video` 或 `image`。
- `reverseModel`：`qwen`、`doubao` 或 `dual`。
- `reverseResult`：结构化反推结果或原始反推文本。
- `prompt`：当前生成 prompt。
- `references`：用户上传的图片、视频、音频及用途。
- `generationRoute`：当前选择的 Dify 生成线路和必填 input key。
- `constraints`：画幅、时长、prompt 字符上限、声音开关、安全清洗规则。

## 输出格式

必须返回结构化报告：

```json
{
  "status": "pass | needs_patch | blocked",
  "score": 0,
  "issues": [],
  "patches": [],
  "rerunNodes": []
}
```

只有缺失信息无法从源视频/图片判断，且必须用户确认时，才返回 `blocked`。

## 完整性检查

### 1. 反推源类型

- `source=video`：必须保留观察到的时间轴、主体动作、运镜、转场、字幕、口播、音频和连续性。
- `source=image`：不要声称观察到了视频动作；可以设计合理动态，但要标记为“设计动作”，不能写成“反推观察到的动作”。

### 2. 主体与物体动作

逐镜头或逐时间段检查：

- 起始状态和结束状态
- 运动方向
- 速度和幅度
- 姿态、手势、表情、产品旋转、形变、开合、灯光变化
- 入镜路径和出镜路径
- 主体、产品、道具、背景之间的互动

关键规则：只描述视频中真实可见或用户明确要求的动作。没有可见位移时写 `无明显位移`。不要因为某个样例里有前后移动、左右移动、转身、手势或产品旋转，就默认所有视频都需要补这些动作。

### 3. 运镜与剪辑

逐镜头检查：

- 景别：特写、中景、全身、俯拍、微距、远景等
- 机位和镜头感
- 运镜：推、拉、摇、移、跟拍、环绕、升降、手持、变焦、固定镜头
- 运镜方向、速度、开始帧、结束帧
- 转场类型和转场时间点
- 镜头之间的动作连续性是否保留

### 4. 场景与风格连续性

检查：

- 主场景和背景
- 前景、中景、背景层次
- 光源方向和色温
- 材质、纹理和细节
- 主体/产品身份是否一致
- 用户参考图是替换产品、人物、角色、背景、首帧、尾帧，还是只提供风格

每个用户上传素材都必须绑定明确槽位。禁止只写“参考图”。

### 5. 字幕、口播和画面文字

如果源视频包含可见字幕或可识别口播：

- 完整转写可读或可听内容
- 保留原始顺序
- 保留重要时间点、说话人和画面位置
- 不确定内容标记为 `听不清` 或 `看不清`

如果没有字幕或口播，写 `无可见字幕/无可识别口播`。不要编造文案。

### 6. 音频

声音默认开启，除非用户明确关闭。

检查：

- 背景音乐情绪、节奏、能量和段落变化
- 动作、转场、物体互动、冲击、UI、环境声等音效
- 有口播或字幕时的音画同步
- 不写具体受版权保护的歌曲名、歌手名、品牌名或“复刻某旋律”

### 7. Dify 线路可运行性

进入生成前检查：

- route 类型匹配任务：文生视频、图生视频、首尾帧、多图参考视频、生图、上传转 URL
- 必填文件 key 和 prompt key 存在
- 参考文件数量、文件类型和线路要求匹配
- 除非用户关闭，`audio=on`
- 长任务使用适合的 `response_mode`
- 失败重跑从受影响节点开始，不默认从头跑

### 8. Prompt 约束

- 最终生成 prompt 必须小于 `maxChars`，默认 2000 字符。
- 优先使用压缩后的结构化中文。
- 清除平台名、账号、水印、精确品牌商标、版权角色、具体歌曲名、复刻/同款等风险词。
- 不要随意删除用户要求保留的产品身份；如果有风险，先请求确认。

## 严重级别

- `critical`：线路不匹配、缺少必填上传、用户要求有声音但 audio 关闭、会阻断生成的安全问题。
- `high`：漏掉真实可见动作、运镜、字幕/口播、参考槽位绑定或连续性。
- `medium`：风格、材质、光线描述太笼统。
- `low`：措辞可压缩或可清洗，但不影响核心结果。

## Patch 规则

- 只 patch 最小必要字段。
- 保留用户手动编辑内容。
- 标记 patch 来源：`observed`、`inferred` 或 `user_requested`。
- 除非用户要求重置，不覆盖整段 prompt。

## 放行门槛

只有满足以下条件，prompt 才能进入生成：

- 没有 `critical` issue
- 所有可见动作和运镜已描述，或明确标注不存在
- 所有用户参考素材已绑定槽位
- 字幕/口播状态明确
- 声音状态明确
- Dify route 输入匹配当前线路
- prompt 长度在限制内
