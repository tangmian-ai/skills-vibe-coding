# 通用Skill模版说明（设计/运营版）

- **适用对象**：设计、运营
- **核心目标**：把用户的简单中文意图，结合运营与设计规则，借助 doubao2.0 生成高质量 Prompt，输出可交付图片。
- **适用业务场景**：
  - **AI商品**：商品精修、商品背景图、商品模特合成/替换
  - **AI人像**：证件照、形象照、创意人像
  - **AI营销物料**：节日祝福海报、小红书大字笔记/人像笔记、电商主图套图
- **模型指令**：以下规则是针对 Trae/Gemini 等模型的强制性约束，请在生成 Skill 文件时严格遵守。
    1. **文件形态**：必须创建名为 `SKILL.md` 的入口文件，使用 YAML Front Matter 定义元数据。
    2. **输入结构化**：在 `步骤 0` 中必须使用 `<input_schema>` 标签定义输入解析逻辑。
    3. **禁止双语标题**：所有标题（H1-H6）及核心字段名称**严禁**使用“中文+（英文）”格式（如：`技能规范 (Skill Specification)`），必须仅使用中文，以节省 Tokens。
    4. **Prompt 语言规范**：生成的 Prompt **必须使用中文**。
    5. **模型无关性**：严禁出现特定模型（Midjourney/Stable Diffusion）的专用指令参数（如 `--iw`, `--ar`, `--v 6.0`, `Steps`, `CFG` 等），应仅输出通用的自然语言描述。

## 2. Skill 工程结构（标准化交付）
建议按以下四层结构组织文件，确保 Skill 的可维护性与复用性。
**核心原则**：资源层文件应保持**细颗粒度**。**请根据实际业务场景创建对应的规则文件**（下方仅为示例，请替换为您实际投放的渠道或品牌风格），Agent 将根据用户输入动态调取，避免 Token 浪费。

```text
ai-image-generation/           # Skill 根目录
├── 名称                       # 元数据：Skill 名称
├── 描述                       # 元数据：Skill 描述
├── 技能规范                   # 核心文件：指令层（Prompt 逻辑）
└── 参考文件/                # 资源层：运营与设计的核心资产库（细分文件，按需引用）
    ├── 主题文案库.md           # [示例] 如：节日/促销/种草
    ├── 通用设计原则.md         # [示例] 如：配色/构图/风格
    ├── 通用禁用词.md           # [示例] 如：侵权/敏感词
    ├── 场景预设库.md           # [示例] 如：室内/户外/纯色背景
    ├── 人像姿态指南.md         # [示例] 如：半身/全身/特写
    ├── 渠道规范合集.md         # [示例] 如：尺寸限制/审核红线
```

- **名称**：Skill 的唯一标识符。**（始终加载，需 < 100 tokens）**
    - ✅ **核心公式**：`物料名称` + `技能`
    - **字数**：10字以内
    - **示例**：电商主图套图技能

- **描述**：简要说明 Skill 的触发规则。**（始终加载，需 < 100 tokens）**
    - ✅ **核心公式**：`技能功能` + `使用场景` + `触发关键词 / 条件`
    - **字数**：50–100 字
    - **推荐写法示例**：
        > 根据用户上传的商品图与输入信息，自动完成精修商品、提炼卖点、文案排版、平台适配，一站式生成主图套图。用户提出 “生成主图 / 主图套图” 等设计需求时使用。
    - ❌ **不建议写法**：
        1. **过于模糊，Agent无法识别**。如：帮助处理工作。
        2. **缺少触发条件**。如：可以处理各种文档和表格。
        3. **空洞重复、无实际信息**。如：做数据相关的事情。
        4. **技术术语堆砌，用户看不懂**。如：实现多层数据模型解析与结构化输出处理。
        5. **格式错误、过长、带特殊符号**。如：【超强技能】可以做表格、PPT、文档、画图、写代码...（超长内容）
    - 📝 **Skill 描述自查表**：
        1. 写清楚能做什么
        2. 写清楚什么时候用
        3. 包含用户常用关键词
        4. 第三人称、简洁通畅
        5. 不写空话、黑话、过长内容

- **技能规范**：Agent 生成 prompt 的执行流程。**（按需加载，建议 < 1000 Tokens）**
    - **拆分原则**：若有大量细节参考内容，**必须**拆分到 `参考文件/` 中实现按需加载。
    - **调用权限**：**只有此文件**可以发起对 `参考文件/` 下文件的调用。
    - ✅ **能写什么**：
        1. 执行 SOP / 步骤
        2. 引用加载说明
        3. 输出格式 / 示例
        4. 执行门禁（必须跑哪些命令/检查）
        5. 必读通用知识（允许，但字符少。目的是减少调用参考文件次数）

- **参考文件**：存放设计/运营规则、文案库等静态知识。**（引用加载，建议 < 5000+ Tokens）**
    - **禁止相互调用**：`参考文件/` 目录下的文件之间**严禁相互引用或调用**。所有规则的聚合与逻辑处理必须在 `技能规范` 中完成。
    - **独立性**：每个规则文件应自包含，仅作为数据源被主 Skill 读取。
    - ✅ **能写什么**：
        1. 不同主题/品类/渠道/行业设计要点
        2. 不同平台设计规范
        3. 不同品类/平台/行业文案生成要点（含禁用词）
        4. 不同作图场景 prompt 填充要点（基于运营要求）
